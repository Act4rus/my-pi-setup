# Pi Setup

`~/.pi/agent` is not just a config dir — it **is** the git working copy of the user's setup repo. Config changes reach the repo by committing them there.

| Remote | URL | Use |
| --- | --- | --- |
| `origin` | `https://Act4rus@github.com/Act4rus/my-pi-setup.git` | the user's fork — push here |
| `upstream` | `https://github.com/davis7dotsh/my-pi-setup.git` | pull updates; push URL is deliberately disabled |

The username in the `origin` URL is load-bearing: the machine's SSH key authenticates as a *different* GitHub account (`FLOWleplusbeau`), so SSH remotes push under the wrong identity. HTTPS + the `gh` credential helper resolves `Act4rus` from the URL, and works without `gh auth switch`.

## Tracked vs. local

Versioned, so put config changes here: `extensions/`, `skills/`, `prompts/`, `themes/`, `AGENTS.md`.

Gitignored on purpose — never commit, never expect them on another machine: `auth.json`, `settings.json`, `sessions/`, `bin/`, `node_modules/`, `.env`.

Two exceptions worth knowing:

- `settings.json` is local, but `settings.example.json` **is** tracked. When you change a preference (theme, model, provider, packages), mirror it into the example file so it survives to the next machine.
- `extensions/cmux-session.ts` is generated by `cmux hooks pi install` and is excluded via `.git/info/exclude` rather than `.gitignore` — keeping it out of the tracked ignore file avoids an upstream conflict. Do not commit it; cmux rewrites it in place.

## Changing config

```sh
cd ~/.pi/agent
# edit extensions/ skills/ prompts/ themes/
npm run check && npm run format
git add -A && git commit -m "..." && git push
```

Prefer **adding a file** over editing an upstream-tracked one. Every edit to `SETUP.md`, `README.md`, `.gitignore`, `AGENTS.md`, or `package.json` is a merge conflict on the next upstream pull; a new file never conflicts.

## Pulling upstream updates

```sh
cd ~/.pi/agent
git fetch upstream && git merge upstream/main
```

Re-run the dependency install afterwards if any `package.json` changed.

## Installing dependencies

`SETUP.md` says root `npm install`, which is **not sufficient** — each extension has its own `package.json`:

```sh
cd ~/.pi/agent
npm install
for d in extensions/*/; do npm --prefix "$d" install --no-audit --no-fund; done
```

Use `npm install`, not `npm ci`: upstream lockfiles have gone out of sync before (missing `@effect/tsgo` linux/win optional binaries), which makes `ci` fail outright. Skipping the per-extension step leaves `effect` unresolvable, and `subagents`, `summaries`, `ask-user`, `file-search`, `git-info`, and `firecrawl-search` silently fail to load. `npm run check` catches this.

## Where pi looks

- `~/.pi/agent/AGENTS.md` — global context, loaded into **every** session in every project. Keep it short; anything long belongs in a skill.
- `~/.pi/agent/SYSTEM.md` — replaces the system prompt entirely. `APPEND_SYSTEM.md` appends to it.
- `~/.pi/agent/{skills,prompts,themes,extensions}/` — user-scope resources, loaded at startup.
- Project equivalents live in `<project>/.pi/` and require the project to be trusted.
